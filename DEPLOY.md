# Чеклист деплоя (Vercel)

## 1. Перед мержем

- [ ] `npm test` — юнит-тесты, словари, API.
- [ ] `npx playwright install chromium` (один раз), затем `npm run test:e2e` и `npm run test:browser`.
- [ ] `npm run dev` → http://localhost:3000. Пройти демо-колоду, переключить RU/EN/UZ, открыть «Библиотеку».

## 2. Переменные окружения

Vercel → Project → Settings → Environment Variables. Всё необязательно: без ключа сайт работает на бесплатном переводчике.

| Переменная | Зачем | Пример |
|---|---|---|
| `OPENAI_API_KEY` | Серверный ключ — ИИ для всех посетителей за счёт владельца | `sk-…` |
| `OPENAI_BASE_URL` | Куда ходит серверный ключ (любой OpenAI-совместимый HTTPS) | `https://api.openai.com/v1` |
| `OPENAI_MODEL` | Модель для серверного ключа | `gpt-4o-mini` |
| `GEMINI_API_KEY` | Серверный ключ Google Gemini (бесплатный, [aistudio.google.com/apikey](https://aistudio.google.com/apikey)). Используется, если `OPENAI_API_KEY` не задан; адрес и модель подставляются сами | `AIza…` |
| `SUPABASE_URL` | Адрес проекта Supabase для аккаунтов (Settings → API → Project URL). Без него кнопки «Войти» нет | `https://abcd.supabase.co` |
| `SUPABASE_ANON_KEY` | Публичный ключ того же проекта: anon key или новый publishable key (`sb_publishable_…`); подходят и имена `SUPABASE_PUBLISHABLE_KEY` / `NEXT_PUBLIC_SUPABASE_*` от интеграции Vercel. Его можно показывать браузеру: доступ к данным ограничивает RLS из `supabase/schema.sql` | `eyJhbGci…` |
| `GEMINI_MODEL` | Модель Gemini для серверного ключа | `gemini-3.5-flash-lite` |
| `ALLOWED_ORIGINS` | Другие сайты, которым можно вызывать `/api/ai` (через запятую). Всегда разрешены домен, на который пришёл запрос, и адреса этого деплоя (`VERCEL_URL`, production-домен) | `https://vocab.example.com` |
| `AI_ALLOWED_HOSTS` | Дополнительные провайдеры для собственных ключей пользователей | `api.fireworks.ai` |
| `AI_RATE_LIMIT` | Запросов с одного IP за окно при серверном ключе | `30` |
| `AI_RATE_LIMIT_BYOK` | То же для запросов с собственным ключом | `120` |
| `AI_RATE_WINDOW_MS` | Окно лимита, мс | `600000` (10 мин) |

После изменения переменных сделайте **Redeploy** — функция читает их при запуске.

Проверка после деплоя (подставьте свой домен):

```bash
curl -s -X POST https://ВАШ-ДОМЕН/api/ai -H "Origin: https://ВАШ-ДОМЕН" -H "Content-Type: application/json" -d '{"action":"status"}'
```

Ожидается `{"status":"ok","serverKeyConfigured":true,…}`. Запрос `GET` должен вернуть `405`, запрос с чужим `Origin` — `403`.

## 2а. Аккаунты (Supabase)

1. Создать проект на [supabase.com](https://supabase.com) (бесплатного плана хватает).
2. SQL Editor → выполнить `supabase/schema.sql`. Он создаёт таблицу `progress` (одна строка на пользователя) и включает RLS: каждый видит только свою строку.
3. Authentication → URL Configuration:
   - **Site URL** — адрес сайта, например `https://vocablurymasterai.vercel.app`;
   - в **Redirect URLs** добавить тот же адрес.

   Ссылки из писем (подтверждение, сброс пароля) ведут сюда.
4. Authentication → Sign In / Providers → Email:
   - вход по почте и паролю должен быть включён;
   - «Confirm email» можно оставить включённым: тогда новый пользователь входит по ссылке из письма.
5. Settings → API: скопировать **Project URL** и **anon public key** в переменные Vercel `SUPABASE_URL` и `SUPABASE_ANON_KEY`, затем сделать Redeploy.

**Что синхронизируется:**
- библиотека: слова, SM-2, история, серия, цель;
- выбор языков и режимов.

**Что не уходит в облако:**
- API-ключ из настроек;
- настройки отображения.

**Как разрешаются расхождения:**
- При первом входе на устройстве его слова объединяются с облаком: для слова, которое есть на обоих, побеждает копия с бо́льшим числом повторений.
- Дальше каждое устройство скачивает чужие изменения при открытии и отправляет свои через 3 секунды после правки.
- Если два устройства правили одновременно, прогресс объединяется так же, как при первом входе.

Почта: бесплатный SMTP Supabase шлёт мало писем в час. Для настоящих пользователей стоит подключить свой SMTP (Authentication → Emails → SMTP Settings).

## 3. Заголовки безопасности (CSP)

Заголовки задаются в `vercel.json`, а `npm run dev` и тесты применяют их же.

- `script-src` разрешает только свои файлы и **хеш** встроенного скрипта темы в `<head>`. После любой правки этого скрипта `npm test` упадёт и покажет новый хеш — его нужно вписать в `vercel.json`.
- `connect-src` — это сам сайт, бесплатный переводчик и те же провайдеры ИИ, что разрешены в `api/ai.js`. Если вы добавили провайдера через `AI_ALLOWED_HOSTS`, запросы через `/api/ai` работают сразу. Прямые запросы из браузера (без сервера) заработают только после того, как хост добавлен в `connect-src`.
- Шрифты лежат в `vendor/fonts/` (`node tools/fetch-fonts.js` скачивает их заново); сторонних CDN нет.
- Проверка после деплоя: в DevTools → Console не должно быть сообщений «Refused to…» / «Content Security Policy»; `curl -sI https://ВАШ-ДОМЕН/ | grep -i content-security` показывает политику.

## 4. Старые клиенты

Контракт `/api/ai` изменился в v2.9: старые версии приложения отправляли готовые `messages` и проверяли статус через `GET`.

- Сразу после деплоя старая вкладка, открытая до обновления, получит `405` на проверку статуса и решит, что серверного ИИ нет. Слова будут переводиться бесплатным переводчиком. Приложение не сломается, просто временно работает без ИИ.
- Service worker работает по схеме «сначала сеть», поэтому при следующей загрузке онлайн пользователь получает новую версию (кэш `vm-v2.9`), и серверный ИИ снова работает.
- Дольше всего (пока не появится сеть) старый код остаётся только у тех, кто открывает сайт офлайн. Им ИИ всё равно недоступен.
- Сторонние скрипты, которые слали `messages` напрямую, теперь получают `400`. Так и задумано.

## 5. Лимит запросов: рекомендации

Встроенный лимит хранится в памяти одного serverless-инстанса: он сбрасывается при холодном старте и не общий для параллельных инстансов. Заголовок `Origin` подделывается скриптами. Если на сайте серверный ключ, добавьте внешний лимит:

- **Vercel Firewall** (проще всего): Project → Firewall → Add Rule → «Rate Limit», путь `/api/ai`, например 30 запросов в 10 минут на IP, действие «Deny». Платформа сама блокирует лишнее до запуска функции.
- **Upstash Redis** (`@upstash/ratelimit`), если нужен лимит в коде: общий счётчик для всех инстансов. Подключается вместо функции `rateLimit()` в `api/ai.js`.
- В кабинете провайдера поставьте **месячный лимит расходов** на ключ — это последняя страховка.

## 6. Откат

- **Быстро:** Vercel → Deployments → предыдущий рабочий деплой → «Instant Rollback» (или «Promote to Production»). Занимает секунды, код не трогается.
- **В коде:** `git revert` нужных коммитов в `main` и обычный пуш — Vercel задеплоит сам.
- Service worker после отката обновится сам: у каждой версии свой `sw.js`, старые кэши удаляются при активации.
- Данные пользователей откат не затрагивает: библиотека в `localStorage`, формат совместим назад (новые поля SM-2 старые версии просто игнорируют).

## 7. После деплоя

- [ ] Открыть сайт в обычном и приватном окне, пройти пару карточек.
- [ ] В Chrome DevTools → Application: service worker `activated`, manifest без ошибок, кнопка установки ⤓ появляется.
- [ ] Включить офлайн в DevTools → Network → обновить страницу: сайт открывается.
- [ ] Если задан серверный ключ: в «Настройки сессии» статус «Vercel ИИ онлайн», новая колода получает подсказки и примеры.
